# Dependency and Format Versions

Last repository inventory update: 2026-09-19. Update this page in the same change as a dependency, image, tool, package, or persistent-format version change.

This inventory records repository declarations. It does not claim that a particular version is deployed to AWS. A `*`, `latest`, caret range, unversioned download, or mutable Docker tag does not identify one reproducible artifact. Package imports inherit the declaration in the consuming package manifest; the paths below enumerate those declarations rather than every import statement. Schema rows also include production callers that reference the version constant or literal. Test fixtures and generated AI model catalog data are excluded.

Most workspaces do not commit a lockfile. Their installed dependency versions can change on the next install even when a manifest is unchanged. The [docs-site lockfile](../site/pnpm-lock.yaml) resolves Markdoc to `0.4.0`; its direct importer does not include the manifest's Vitest dependency. Do not infer service dependency versions from that lockfile or from a test runner's cache.

## Verified NATS releases

The Go broker pins NATS Server **2.15.0** in its module manifest. Snapshot commands call NATS APIs directly. The Go test image includes **NATS CLI 0.4.0** from the pinned `natsio/nats-box` image only to verify snapshot compatibility in both directions; the production image contains neither that CLI nor an operational shell. See the official [server release](https://github.com/nats-io/nats-server/releases/tag/v2.15.0) and [CLI release](https://github.com/nats-io/natscli/releases/tag/v0.4.0).

The local `synadia/nats-box:latest` diagnostic container is a separate image declaration. It is separate from the pinned CLI in the Go test runner.

## Updating a version

1. Find the dependency in this page and inspect every listed declaration. Search the repository for its package name, image repository, version constant, and existing version string to catch declarations added since this inventory.
2. Check the upstream release notes and migration guidance. For images, verify the intended Linux architectures and record the multi-platform manifest digest. For package ranges, retain the declared range in this page; report an installed version separately with its lockfile or image digest.
3. Edit the authoritative declarations and affected consumers together. Keep workspace package names, Docker build contexts, Compose mounts, and package exports synchronized.
4. Run the applicable Dockerized tests when authorized and the quality runner with autofix. A NATS upgrade also needs broker-config validation and snapshot/restore compatibility checks.
5. Update the date, versions, types, and all declaration paths here. Record a compatibility or migration constraint beside the entry when one exists. Do not replace a pin with `latest` merely to remove maintenance work.

Provider SDK upgrades that change API behavior must follow the [AI Model Registry contract](../../services/ai-model-registry/documentation/AI-MODEL-REGISTRY.md). Provider models, API model versions, and parameter schemas remain in that registry; duplicating its catalog here would create conflicting records. The provider-usage contract is served by another repository and requires explicit permission plus coordinated changes on both sides.

## Images, runtimes and package managers

The [Caddy Dockerfile](../../services/caddy/Dockerfile) uses the same pinned Go builder as NATS and ships a static executable with CA roots. Its [module manifest](../../services/caddy/go.mod) pins Caddy `v2.11.4`, CertMagic `v0.25.3`, the Route53 plugin `v1.6.2`, AWS Lambda Go `v1.55.0`, AWS SDK v2 core `v1.47.0`, config `v1.33.5`, S3 `v1.113.1`, Secrets Manager `v1.50.0` and CloudWatch `v1.72.0`. The [checksums](../../services/caddy/go.sum) record the resolved graph. The runtime uses Go APIs for AWS calls and certificate handling.

The embedded Go build and its dedicated test/quality runners use `golang:1.26.8-bookworm@sha256:9fdc884aacc3bec89b20ffc69f4bb369c78210e3e4f600387b5128b12c199f81`. The linter binary comes from `golangci/golangci-lint:v2.13.2@sha256:ba07dffad130794ae79ebaa0056809d18c0168f3f846480ffd3eb6c04578b83d`. These pins appear in [the NATS Dockerfile](../../services/nats/Dockerfile), [the Go test runner](../../services/go-test-runner/Dockerfile), and [the Go quality runner](../../services/go-quality-runner/Dockerfile). The development target installs `golang.org/x/tools/gopls@v0.22.0` and `github.com/go-delve/delve/cmd/dlv@v1.27.2`; `gofmt` comes with Go. `GOTOOLCHAIN=local` prevents an implicit toolchain upgrade.

The Go service pins NATS Server `v2.15.0`, `nats.go` `v1.51.0`, NATS JWT `v2.8.2`, and NKeys `v0.4.16` in [go.mod](../../services/nats/go.mod). [go.sum](../../services/nats/go.sum) records resolved module checksums. Runtime-registration schema 1 is validated by [the Go declaration validator](../../services/nats/internal/policy/registration.go). Application policy schema 3 is authored in [policy.ts](../../packages/lixpi/nats-subject-registry/src/policy.ts). Local runner image aliases are `lixpi/go-test-runner` and `lixpi/go-quality-runner` in their root Compose include files.

The [native storage test command](../testing/TypeScript/TESTING-GUIDE.md) uses the isolated `nats:2.15.0-alpine@sha256:017eb6d9ec0eda3b7ba4d7858298ef58e4ccebdf7257692b97059dadf29d4552` fixture image.

The Go broker has no cloud-provider SDK dependencies. [Filesystem maintenance](../../services/nats/internal/maintenance/files.go) uses the Go standard library. The separate [AWS deployment adapter manifest](../../infrastructure/pulumi/src/resources/NATS-cluster/deployment-adapter/package.json) declares `@aws-sdk/client-cloudwatch`, `@aws-sdk/client-s3`, `@aws-sdk/client-secrets-manager` and `@aws-sdk/lib-storage` at `*`; its image pins Node 24 Alpine in its own Dockerfile and copies the binary from its supplied `NATS_IMAGE` build argument. Those packages also appear as infrastructure development dependencies for mocked adapter tests. Neither the adapter nor its dependencies are included in the broker image or Go module.
