# Progress timeline

`createProgressTimeline` renders ordered, nested progress without owning any domain state. Callers project reasoning, capability, tool, skill, or media-generation events into `ProgressTimelineItem[]` and update the same instance with `setItems`. Optional `source` metadata renders a compact type-and-name label, plus an optional provider icon. A source-labeled parent may omit `title` so that provenance itself becomes the disclosure heading instead of forcing a redundant caption.

The component distinguishes pending, running, completed, attention, failed, cancelled, and skipped work. `children` provide the sub-item lineage beneath a broader operation. Running items always expose their live summaries. `showSummaryWhenCollapsed` keeps an ellipsized one-line slice visible while collapsed; `hideSummaryWhenExpanded` lets a host suppress that same text when a richer detail block is its expanded representation, preventing duplicated reasoning. Attention, failed, and cancelled items open automatically so their result is surfaced, but the user can collapse them manually; that choice survives streamed updates. Clean completed items collapse by default, while pending and skipped details remain manually expandable. `defaultViewMode: 'focused'` retains only running or issue rows and the ancestor chain required to locate them; clean completed, pending, and skipped siblings stay hidden at every nesting level. A host that sets `preserveTopLevelItemsInFocusedView` keeps every top-level row in focused mode while filtering only inactive nested branches, so completed and not-started operations remain visible as collapsed headings around expanded active/problem work. `expandAllItemsInAllView` makes `setViewMode('all')` recursively open every included item at every depth. Switching either direction clears stale per-item disclosure overrides: focused mode returns to collapsed clean roots plus automatically opened active/problem paths, while all mode starts completely expanded and still permits individual rows to be collapsed afterward. Item disclosure and view mode survive streamed updates when the caller supplies a stable `rippleClockId`. Summary- and meta-only updates mutate the existing text nodes, preserving each item row, rail, and running ripple; structural, status, provenance, or disclosure changes rebuild the affected timeline structure.

An item may carry an opaque `detail` payload that the host expands through `renderItemDetail`, keeping the timeline free of any domain knowledge about what a detail contains. Detail blocks render inside the disclosure region alongside the summary and children, and an item with only a detail is disclosable on that basis alone. Because a detail block can own hover cards and popovers, it is reused across rebuilds whenever its identity is unchanged — `getItemDetailKey` supplies that identity, defaulting to the payload's JSON — and its optional `destroy` runs exactly once, when the block leaves the rendered tree or the timeline is destroyed. A host that returns an empty key declares that the payload has nothing to render, and the item is treated as having no detail, so no disclosure toggle opens onto an empty region.

Source type labels use regular text weight, source names remain bold, and provider icons are centered on the shared source line. Optional `meta` text keeps a compact result such as an overall score visible even while details are collapsed. Running markers use the same three-path SVG and staggered D3 expansion used by the product graph: the middle layer expands to 1.72×, the outer ring follows after 220 ms and expands to 2.05×, and the center remains fixed. `createProgressRippleIcon` is exported for other UI-kit consumers that need the same active marker.

Status markers vertically centre on the item's first text line. Hosts inject `--progress-timeline-title-size` (and `--progress-timeline-source-size`), so the marker offset and the rail's start are derived from `--progress-timeline-first-line-height` — computed per item from whichever line renders first (`data-leading` is `source` when a provenance row leads, `title` otherwise) — never from hardcoded pixel offsets.
