# Lixpi Canvas Components

[Workspace composition](docs/WORKSPACE.md) covers the canvas host, node types, interactions, media, persistence and disposal. Reusable rendering contracts are documented in [Canvas Engine](../canvas-engine/README.md) and [Canvas Components](../canvas-components/README.md). See [license and dependency notices](NOTICES.md).

`@lixpi/canvas-components-lixpi-specific` adapts the reusable canvas packages to Lixpi's workspace, Asset and generation contracts.

`WorkspaceGenerationHandlers` under `/frontend/media` coordinates image/video stream events with API geometry, run trackers, marker settlement, decoded-frame handoff and Asset refresh. It owns its two event subscriptions and rejects events from another workspace or an obsolete scene. Resource and rendering callbacks are checked against the originating scope before subsequent work. Its ports supply transport, editor and view operations; the event owner does not import application services or stores.

## Shared projection

`WorkspaceGeometry` composes the engine's rectangle collision resolver with Lixpi media footprints, branch spacing and generated-tree layout. Supply live world coordinates, marker dimensions, pending-frame state, viewport and pane size. Pending media reserves its final horizontal width while connector anchors track the compact circle. Resolved media reserves title and action chrome without shifting connector anchors. Geometry methods read their instance ports and do not publish state or persist changes.

`createLixpiCanvasSettings` from `/frontend/settings` returns independent product presets for canvas connectors, selection, media, glass, outlines, branch markers, collision flows and persistence timing. API layout constants remain the shared geometry contract. Call the factory without arguments for the product defaults or supply palette overrides. Mutating one result does not affect other canvases or the shared constants. Generic controls and their settings remain with UI-kit and the application theme.

The root and `/shared` entrypoints contain branch lineage, marker dimensions, generated-output collision envelopes and authoritative snapshot admission. The API and browser use the same implementation:

```typescript
import {
    applyCanvasGeometryUpdateToState,
    getGeneratedMediaPreFrameLayoutRect,
    rebalanceBranchTreesAndResolve,
} from '@lixpi/canvas-components-lixpi-specific/shared'
```

These adapters preserve the persisted types from `@lixpi/constants`. They use engine geometry without exposing browser code to server consumers. The API remains authoritative for generated-output identities, branch topology, membership and cancellation.

`computeWorkspaceDragPlan` applies Lixpi's lineage-marker collision and proximity policy to the engine's generic selection/descendant drag plan. Product node kinds are inspected here, not in engine geometry.

`GeneratedMediaRebalancePipeline` reserves transient pending-media geometry, lays out API-declared branch trees and removes its temporary layout proxies before returning persisted node geometry. Geometry callbacks and spacing settings are explicit inputs. Marker reflow preserves started and manually positioned markers. Reference-root placement and branch-lineage gap normalization use the same shared package in browser and backend callers.

Workspace render-state adapters supply generated-output replacement rules and visual identity to engine reconciliation. Pending user edits remain visible until acknowledged; completed generated outputs cannot be replaced by matching stale pending nodes. Workspace route/loading values map into neutral scene-transition inputs. The adapters preserve authoritative nonvisual fields and leave viewport ownership with the caller.

Shared modules must not import a frontend barrel, UI-kit, Pixi, application stores or service implementations. Browser components receive infrastructure through typed package-owned ports.

Marker ownership and settlement rules keep preflight previews and API-planned markers from appearing as duplicate nodes. Reference-resolution presentation chooses which marker displays an API-reported unresolved binding. Review helpers combine persisted Asset review state with live canvas lineage. Workspace panel state drops stale context-node references and invalid details targets. These are presentation decisions over supplied state, not generation or membership authority.

Generation recovery projects authoritative request snapshots and events onto operation and output nodes, preserving progress and terminal failure presentation. Event admission checks the supplied workspace and thread identities. Membership rebasing preserves concurrently added nodes and edges while respecting the complete removed-node set. These shared functions have no transport or store dependency.

`WorkspaceMediaOperationRecovery` owns per-view request recovery through fetch, replay and subscription ports. It subscribes before replay, deduplicates live and replay stream sequences, follows replay pages and rejects older request revisions. Progress events use a separate application path that preserves mounted node content. Clear it on scene replacement; destroy it with the view. The subscription port returns the disposer for that specific listener, so other views using the same subject remain subscribed. Late fetches, replay pages and live callbacks cannot update a replaced scene.

`CanvasGenerationEvents` maps supplied media/control segments into per-instance image/video subscriptions. Each subscription returns its own disposer. Disposing one owner cannot replace or clear another canvas's listeners. Callback payloads are isolated, removed listeners are skipped during dispatch, and callback failures reach the supplied error handler without skipping sibling subscriptions. Editors forward through `CanvasConversationRun`, which checks workspace, conversation and scope before routing. Destroy the event owner with its canvas.

`/frontend/connectors` supplies `WorkspaceConnectionManager`, which configures engine connections with Lixpi marker, media and message-anchor policies. Callers supply roots, viewport operations, errors, mutation callbacks and connector settings. `createWorkspaceConnectorSettings` creates independent settings objects from a supplied theme color. Branch-marker media port helpers read persisted provenance and group image/video outputs into their displayed connector circles; provider IDs and generation behavior are not defined here.

`/frontend/loading` supplies `createWorkspaceLoadingOutline`. It maps injected workspace/media settings into the reusable loading overlay, including generated-output-relative circle sizing, lap speed and workspace error text. The host supplies its pane, settings, retry callback and optional error handler. Import `@lixpi/canvas-components/styles/loading-overlay` for the surface styles.

## Media rendering

`/frontend/nodes` supplies `WorkspaceNodeShells`, which adds Lixpi selection rules, resize artwork and media playback gestures to engine node shells. Its ports provide world bounds, stacking order, zoom, geometry actions and playback. It preserves editor click handling and opens nonselectable branch details only from the native click. `replace` retains the mounted node until replacement content succeeds. `clear` removes a scene's surfaces; `destroy` also prevents new mounts. Import `/styles/nodes` for the product shell and handle styles. The optional `--workspace-resize-handle-color` property overrides the handle artwork color.

`OperationStatusNode` mounts upload and generation status cards through those shells. Verification, cancellation and editing are action ports; their abort signal marks the end of the node's UI lifetime. Accepted transport work is the host's responsibility. Shell removal also disposes content listeners and prevents late action failures from changing the detached card. Import `/styles/operation-status` for its styles; the dismiss artwork comes from UI-kit.

`WorkspaceDocumentNodes` owns document cards and waits for supplied document content before calling its editor port. It owns editors per placement, so two nodes referencing one Asset have independent cleanup. Shell removal aborts lease callbacks and destroys the editor. Failed mounts use UI-kit's error placeholder and retry only the affected editor. `syncDocuments` mounts newly available content; the editor's authority handles subsequent document updates. Import `/styles/document-node` for card-specific editor styles.

`WorkspaceCapabilityNode` supplies the canvas host for module-published Capability Artifact factories. Ports resolve definitions, Asset documents, references and editors. The module still owns its schema and body implementation. The host validates the supplied snapshot, loads missing reference metadata, coalesces height changes and disposes partial mounts. References and editors have idempotent release functions, so module cleanup and shell cleanup cannot destroy them twice.

`WorkspaceNodeShells.createBranchMarker` applies branch identity attributes and native click-to-inspect behavior without click selection or resize handles. Shared prompt helpers preserve reference atoms and their order when truncating previews. `BranchMarkerPromptParts` receives a reference renderer and owns each returned preview; destroy it when replacing marker content. `createBranchReferenceResolution` composes the same renderer with an API-provided candidate set and an injected resolution action. It ignores choices outside that set and suppresses late failures after disposal.

`BranchMarkerContent` composes prompt previews, reasoning, model tooltips and supplied progress/reference-resolution views. It disposes those children together when replaced. `BranchMarkerActions` renders stop or review actions and owns dropdown cleanup. Its callbacks receive user actions; the host supplies request state and handles transport. Import `/styles/branch-marker` and supply the prompt-reference palette through the host theme. UI-kit owns tooltip/dropdown implementations and artwork.

`BranchCapabilityProgress` tracks ordered events per conversation, ignoring repeated sequences. Clear it when releasing a workspace. `buildBranchMarkerProgress` projects supplied request nodes, Capability runs and canonical trace handles into the progress timeline state without fetching data or changing request authority.

`BranchMediaModelCircleStyles` bakes the configured glass treatment and encodes UI-kit's texture artwork for model circles. Each instance owns its cache and includes its material settings in cache keys. `clear()` releases the cached strings. Generic color conversion and encoding functions come from UI-primitives.

`WorkspaceNodeRegistry` combines DOM adapters with media registrations for every Canvas node kind. Media receives world bounds; DOM content receives bounds local to the engine's content root, avoiding duplicate world offsets. The scene owns replacement, selection, visibility and disposal. `createWorkspaceConnectionPolicy` reads `WorkspaceConnectionNodeData` from engine nodes and the persisted `WorkspaceEdge` from edge data; layout uses live engine coordinates.

`WorkspaceDomNodes` mounts shell content through document, Capability, operation and branch factories. Geometry changes retain editor instances. Changing an editor-backed node's Asset replaces its content; operation changes replace the status card. Scene removal disposes its shell and content together. Factories must register child cleanup with the supplied shell lifetime.

`WorkspaceEdgePorts` projects each persisted edge endpoint into a distinct stable port. It retains `sourceT`, `targetT`, handles and message metadata in edge data. Optional live attachment values affect presentation without overwriting unchanged persisted endpoints during reconnection. `resolve` accepts only endpoints belonging to its projection; clear the instance when releasing the scene.

`WorkspaceConnectionProjection` combines those ports with parent/world geometry and compact connector footprints. It preserves hidden edges during edits to visible connections and ignores late changes to edges already removed from authoritative state. `WorkspaceMediaLayer.connections` exposes the controller-owned connection controls; `onEdgesChange` returns the translated workspace edges for persistence. Lixpi does not enable proximity connections.

`/frontend/media` supplies `WorkspaceMediaLayer`. The host provides its pane, viewport mount, node geometry/DOM ports, visible-node projection, asset lookup/source ports, settings, connector marker artwork and intrinsic-size/playback callbacks. The package projects canvas nodes, ready Asset renditions and transient generation frames into one node registry. Included parents retain parent-relative coordinates; children of filtered parents keep their world position. The engine owns culling, resources and renderer lifetime; Canvas Components owns image/native media, glass and outlines. `setGlassTargets` accepts explicit DOM elements, so rendering never searches the application's document for toolbars or composers.

The media layer mounts a `CanvasController` without automatic input bindings and forwards scene, selection and viewport changes. Selection synchronization preserves the controller's existing marquee origin so a marquee-selected single node keeps its group overlay after rendering catches up. Its `worldElement` is the engine's transformed DOM root inside the supplied viewport mount. Leave the containing mount untransformed. `getNodeBounds` returns world geometry; mounted content uses local coordinates. The layer owns product effect targets and Asset projection; its `canvas` controller owns the scene, renderer and installed input controls. The containing workspace supplies product interaction callbacks through that controller.

Import `/styles/workspace-layer` and use `workspace-viewport-mount` on the containing DOM mount. The engine world root carries `workspace-viewport` for canvas content portals. Branch-marker promotion and settlement update the scene; they must not replace or remove registered DOM elements directly.

`refreshAssets` updates descriptors without reloading pixels on title-only revisions. `retryAssetTextures` explicitly retries failed sources. Pending image frames remain displayed until a declared final original decodes, and subsequent generated-image callbacks preserve the resolved geometry. The `playback` API exposes native elements and playback controls for the host's media chrome without exposing Pixi containers.

`WorkspaceVideoChrome` places UI-kit's video controls below ready video nodes and forwards surface drag, corner resize and double-click playback through supplied callbacks. Mount its `element` in a viewport-synchronized overlay and import `/styles/video-chrome`. `sync` retains controls while the native element is unchanged; `update` accepts live world bounds. Removal returns borrowed videos to their original host and releases control and surface listeners. Its settings extend the shared UI-kit controls with canvas spacing and zoom scaling.

`GeneratedOutputNodeChrome` composes a supplied model badge and title editor with UI-kit's shared footer. Media and Artifact variants use the same details/progress controls. Supplied review state controls acceptance, rejection and replay actions; pending frames hide the model badge and review actions without hiding details or progress. `setGeometry` positions the strip in screen coordinates with bounded zoom scaling and keeps the title above the node. `update` changes progress and selection without replacing the editor. Title mounts return a disposer owned by the chrome. Import `/styles/output-chrome` for the Lixpi treatment; UI-kit owns the underlying controls and artwork.

`WorkspaceOutputChrome` coordinates those footers with pending model icons and a supplied `WorkspaceVideoChrome`. Mount its `element` and `pendingElement` directly in the pane. Asset, document and trace revisions control replacement; progress, selection and geometry updates retain title editors. Its ports supply Asset lookup, descriptors, model badges, leased titles and review actions. `schedule` coalesces animation frames; `clear` releases content and cancels pending work; `destroy` also removes both layers. Failed partial mounts release their children and allow an explicit retry. Video playback remains owned by the separate video component.

`/frontend/progress` supplies the generation pipeline view, using UI-kit's recursive progress timeline and disclosure artwork. Import UI-kit's `/styles/progress-timeline` and this package's `/styles/progress`. Pure terminal-state and history-adoption rules live under `/shared`. Each view has a distinct accessible timeline target and cancels its own pending layout callbacks on disposal.

`/frontend/review` supplies the output-details frame and its single scroll body. The caller mounts the node's metadata and history content and returns its disposer. Import `/styles/output-details` for the frame styles. Generic side panels and tooltips remain UI-kit components.

`WorkspaceOutputReview` owns acceptance, rejection and regeneration. Ports provide Asset metadata, sealed provenance, authoritative review requests and generation submission. Replay preserves the recorded prompts, lineage, references and model configuration. Each action captures the workspace and scene; `clear()` invalidates pending UI work and `destroy()` also prevents new actions. Accepted transport requests may finish after disposal, but their responses cannot update a replacement canvas or start another generation.

`WorkspaceGenerationHistory` owns a read-only conversation projection, reasoning badge, reference previews and progress timelines. Supply the ProseMirror editor through `mountEditor`, and supply Asset rendition paths and authorization through the context environment. `mountWorkspaceMediaHistory` selects the generated turn before mounting. Aborting or destroying the view cancels both thumbnail and popover hydration and releases editor-created timelines. An editor can release its returned timeline early without causing duplicate disposal.

`WorkspaceHistory` under `/shared` selects branch and media targets from supplied scene snapshots. It prefers sealed provenance for media, matches Artifact history to its generation request, and preserves prompt reference atoms. Active, pending, Artifact-backed and single-turn markers can use the latest conversation turn as a fallback; unrelated turns are not substituted for Artifact history. The class reads through ports and does not subscribe, write state or choose generation topology.

`WorkspaceGenerationVisuals` under `/frontend/media` projects supplied image/video trackers and reference sets into traveling outlines and pending hit areas. It owns decoded-image flags and completion timers. A completed image keeps its original-rendition outline until pixels decode or its timeout expires. Replacing a run or clearing the scene invalidates earlier timer callbacks, including callbacks for a reused node ID. `clear` releases scene-specific visual state; `destroy` also stops new work. The caller retains ownership of the generation tracker maps and authoritative run events.

`WorkspaceMediaAnalysis` under `/shared` requests descriptions of media Assets, retries unavailable descriptions and refreshes completed Assets until sealed provenance is available. The API selects the authorized image or video still. The owner waits briefly for node insertion, coalesces pending requests and cancels its timers on `clear()` or `destroy()`. Workspace, scene and Asset identity checks prevent late responses from changing a replacement node. Improved text descriptors trigger an Asset reload through the supplied port; the canvas does not generate text descriptors itself.

`WorkspaceCanvasMenu` under `/frontend/menus` composes UI-kit's BubbleMenu with canvas media and edge actions. Node menus follow the node shell's screen rectangle; edge menus use the supplied connector midpoint. The owner clears action targets when geometry disappears or the context changes, and releases item listeners even if menu disposal fails. The caller supplies action ports and the live visual scale. BubbleMenu's implementation and general positioning behavior remain in UI-kit.

`CanvasConversationEditors` under `/frontend/workspace` owns hidden editor mounts for canvas generation. A mount receives its container, abort signal, current-instance check and resource registration function. Register the editor, streaming service and controller binding with that scope as each is created. Replacing a conversation aborts its previous scope before creating the replacement; deferred teardown is tied to that scope and cannot remove a newer editor for the same conversation. The application supplies the generic ProseMirror driver and transport. `clear` permits remounting, while `destroy` also removes the hidden host and rejects further mounts.

`buildCanvasConversationContent` under `/shared` constructs the persisted conversation document from composer data and supplied message identity. It uses ProseMirror's shared serializers for model selections, configuration groups and Capability inputs. Absent settings stay absent, and each selection axis follows its supplied single/multiple flag. The shared prompt helpers retain visible reference labels and repeated mentions while deduplicating the separate list of canvas node IDs.

`WorkspaceBranchActivity` under `/shared` derives pending and stop-control state from supplied nodes, Assets and run placements. It recognizes persisted pending media through lineage assignments or authoritative request IDs, so reload does not depend on transient placement maps. Completed Artifacts alone do not conclude a media group. Cancelled requests and completed media retain precedence over stale pending presentation. These rules project API-owned state and do not assign branch topology.

`WorkspaceGenerationPlacements` owns transient placement, marker-alias, cancellation and UI-phase maps for one canvas. It recovers pending markers from supplied persisted nodes using lineage, run identity and reasoning slots. Adopting a request copies its preflight run sets, so sibling requests do not share mutable sets. Started media and cancellation override stale pending presentation. Call `clear()` when releasing the scene; persisted nodes can reconstruct active marker ownership after reload.

`WorkspaceCanvasActions` under `/frontend/workspace` creates documents and imports uploaded or remote media. It owns upload placeholders, insertion dimensions, membership preparation and error presentation. Upload ports perform authorization before calling `onStart`; they send bytes only if that callback admits the captured canvas. Asset creation or an accepted upload may finish after the view closes, but node preparation and publication require the original workspace, organization and view revision. The supplied membership port owns durable writes.

`WorkspaceCanvasChrome` owns the toolbar, upload submenu, zoom label and canvas mount elements. It exposes explicit pane, viewport, media-mode and model-menu mounts plus glass targets for the renderer. Supply action callbacks, the owner Document, palette and panel settings. Import `/styles/canvas-chrome`; theme variables stay on the component root. Its destruction removes the DOM and outside-click listeners. The shared tooltip provider and generic controls still come from UI-kit.

`WorkspaceReferenceProjection` under `/shared` maps prompt references to existing canvas placements or off-canvas preview descriptors. It projects branch prompt parts and trace handles from supplied metadata. Prompt mentions keep their order and repetition, while media trace handles follow the provenance Asset list, including an explicitly empty list. Older node-based provenance resolves through the supplied scene. Asset titles and kinds come from the Asset port, and hydrated document titles come from a separate read port.

The same entrypoint supplies `mountAssetSubjectIdentityControl`. Pass the Asset, host element and `attestSubjectIdentity` callback. The control serializes selections and ignores late results after switching Assets or disposal; the host handles transport and authoritative store updates. Multiple controls can display the same Asset without sharing dropdown IDs.

`WorkspaceAssetViews` owns canvas titles, metadata editors and Asset details. Use separate instances for canvas chrome and the details sidebar. Ports provide Asset snapshots, content documents, editor construction and revisioned mutations. Mutations must apply their authoritative store updates even after a view is disposed; the package suppresses subsequent UI callbacks. Metadata saves serialize repeated focus exits and read the latest Asset revision before each write. Content editors receive explicit workspace/Asset authority and ignore lease callbacks after disposal. Scope controls retain their originating workspace and user identities. Import `/styles/asset-views` for metadata and diagnostic presentation.

`/frontend/menus` supplies canvas media/edge action items for UI-kit's `BubbleMenu`. Infrastructure actions are callbacks; each item owner keeps its own active node/edge and removes listeners on `destroy`. The menu and its item owner each need disposal.

## Workspace surfaces

Import `/styles/workspace` for the workspace component stylesheet. Application palette overrides can remain in the mounting application. `WorkspaceCanvasHost` supplies optional capability-library commands and external navigation; the component does not subscribe to application window events itself.

`WorkspaceAssetProjection` under `/shared` loads canvas references before lineage sources, prioritizes the active conversation and batches missing document snapshots. Its host ports supply transport and cache access. A load captures its workspace and admission callback; a replacement load or departed workspace cannot publish late results. `WorkspaceAssetSynchronization` owns its event subscription and reconciliation timer. Destroying it closes admission before releasing resources, and a deletion or newer refresh invalidates earlier replies.


`LixpiWorkspaceCanvas` (or `createWorkspaceCanvas(options, host)`) composes the workspace renderer through `WorkspaceCanvasHost`. The host supplies Asset snapshots and transport, generation requests, catalogs, media authorization, storage, theme settings and editor factories. `WorkspaceCanvasEditors` keeps the concrete ProseMirror driver and generic control factories outside the package. The renderer owns node selection, geometry, canvas menus, generated-output projection, panels and instance cleanup. `WorkspaceCanvasSurface` mounts this renderer through its factory port. Destroying a renderer closes callback admission and attempts all registered cleanup even when one component fails; accepted persistence writes remain owned by the workspace session.

The renderer delegates bounded UI and lifecycle concerns to port-driven workspace owners. Selection and pointer behavior live in `WorkspaceCanvasSelection` and `WorkspaceCanvasInteractions`. `WorkspaceCanvasLibraries`, `WorkspaceCanvasAssets` and `WorkspaceCanvasContext` adapt libraries, Asset views and prompt context without importing application stores. `WorkspaceMediaGeometry` and `WorkspaceMediaReplacement` handle intrinsic media sizing and replacement uploads. `WorkspaceBranchMarkerModels`, `WorkspaceBranchMarkerProjection`, `WorkspaceBranchMarkerPresentation` and `WorkspaceBranchMarkerGeneration` handle branch metadata, geometry projection, DOM presentation and cancellation. `WorkspaceOperationStatusNodes`, `WorkspaceGeneratedOutputDetails`, `WorkspaceCanvasVisibility` and `WorkspaceCanvasThreadState` handle operation recovery, output review details, render filtering and conversation state. `WorkspaceCanvasRendering` coordinates scene transitions through supplied ports. Theme application and cleanup remain stateless helpers. Each owner can be constructed and tested without mounting the complete workspace renderer.

`WorkspaceNodeDeletion` under `/shared` coordinates selection deletion through output review, run cancellation and Asset membership ports. It attempts each selected node after a per-node failure, prunes context chips with deleted markers and finishes local removal when an Asset is already missing. Request reads and accepted detach replies retain their originating workspace/scene; obsolete callbacks cannot publish into a replacement view or unlock a newer deletion.

`WorkspaceNodeGestures` coordinates workspace selection, drag/resize chrome, parent-relative geometry and manual marker positions through engine gesture APIs. It owns pan locks and click-suppression timers. Each gesture captures its workspace, scene and instance revision, so replaced gestures cannot alter current geometry. Collision policy remains in `WorkspaceGeometry` and solving remains in the engine. `clear` releases an interaction during scene replacement; `destroy` closes admission and attempts every cleanup even after a failure.

`WorkspaceMediaTrackers` under `/shared` owns the image and video run maps. It matches API run identities, records Asset readiness and preserves active media through delayed store snapshots without duplicating an existing node, Asset or generation run. Deleted nodes release tracker aliases and completion visuals. `clear` releases scene state; `destroy` also closes tracker admission. The same entry point exports the tracker contract and alias helpers used by generation visuals.

`WorkspaceApiCanvasGeometry` under `/shared` applies authoritative geometry and node snapshots without starting a persistence write. Revision guards belong to the workspace and scene; an incomplete update can be retried at the same revision, and a replacement scene starts its own revision history. Preflight reconciliation prepares marker aliases before cleanup. Each projection has a ticket so reentrant updates, scene replacement and disposal suppress obsolete publications and view callbacks. Ports reconcile mounted nodes, clear media trackers and retain the visual state until its store acknowledgment arrives.

`WorkspaceGenerationSettlement` under `/shared` tracks run completion, applies API lineage plans and clears request presentation. It retains shared placement and reference state while sibling media runs remain active, removes late preflight markers on final completion and delegates conversation refresh and editor teardown through ports. Marker settlement can preserve live geometry or resize content while retaining a manual position. A replaced workspace or scene stops the remaining commit, rendering and editor callbacks.

`WorkspacePreflightMarkers` under `/shared` projects submitted and persisted conversation selections into temporary canvas markers. It restores detached conversation markers, consumes API-provided lineage marker identities and delegates placement to `WorkspaceLineageProjection`. Ports supply conversation snapshots, active-run identities, marker resizing and scene commits. Preparation stages node and alias changes together, so a failed resize or replaced scope cannot publish a partial set. The commit remains transient; the API owns durable generation topology. Appending views after a commit also checks the originating workspace and scene.

`WorkspaceBranchMarkerHandoff` under `/shared` promotes transient markers to API-planned identities, replaces their placement aliases and incident edges, and clears pending presentation when media takes over. Its commit port must apply transient canvas state without starting a persistence write. Settlement can preserve live geometry; manually positioned markers retain their location when their content resizes. The supplied scope identifies the workspace and scene, and the handoff stops invoking UI callbacks if either changes during cleanup or commit. Regeneration reuses the API-declared parent and reports a missing parent instead of creating another one.

`WorkspaceLineageProjection` under `/shared` projects API-declared branch markers, parent edges, reasoning identities and sibling order. It reads per-canvas placements and scene geometry, preserves mounted authoritative marker positions and delegates conversation-sized marker content to a supplied resize port. Missing API marker plans do not create inferred lineage. Explicit media references use world-space bounds; generated image and video outputs share ordering. The projection keeps no scene cache, so replacing the supplied snapshot and clearing placements removes the old scene's references.

`WorkspaceCanvasSurface` under `/frontend/workspace` owns the mounted workspace view, its toolbar, store reconciliation, document/conversation projection, membership preparation and viewport lease. The host supplies snapshots, document reads, subscriptions, Asset transport, session lookup, browser storage and renderer construction through typed ports. Store callbacks that fire during rendering are reconciled after the current pass. Navigation and unload invalidate pending view actions; accepted transport writes remain attached to their originating session. Destroy the surface when unmounting. Disposal flushes pending viewport intent with the final renderer geometry, releases subscriptions and attempts every child cleanup even if one fails. Generic controls and icons come from UI-kit.

`CanvasGenerationSubmission` under `/shared` persists the initial conversation document and admits its editor through supplied ports. Submission captures workspace, organization, scene and composer values before waiting for Asset creation. Clear it on scene replacement and destroy it with its canvas. Accepted Asset creation may settle after disposal, but obsolete submissions cannot install editors or retarget a replacement scene. The installed editor receives the persisted message and its document version; provider selections and configuration serialization use the shared composer contract.

`WorkspaceGenerationContext` under `/shared` projects explicitly attached canvas nodes into candidate and context snapshots. The host supplies Asset descriptors and rendition paths. Images use preview renditions and videos use representative frames; snapshots do not contain unselected workspace nodes. These are non-authoritative request inputs. The API authorizes Assets and assigns lineage roles.

`CanvasConversationRun` under `/frontend/workspace` coordinates one hidden conversation editor and its transport within a `CanvasConversationEditors` scope. It preserves submitted prompt references, prepares media preflight, projects streamed content and schedules settled-editor teardown. Its editor port exposes content reads, persisted-message submission and disposal without exposing ProseMirror objects. Transport connects before editor activation because activation can submit queued work synchronously. Removed scopes cannot publish content, submit new requests or tear down replacement editors; already accepted transport work may still settle.

`WorkspaceConversationRuns` tracks active and settled conversations alongside their hidden editor scopes. Settling stops receiving presentation but retains the editor until teardown. `clear()` releases active editors and pending activation before a scene switch, without cancelling backend generation. Reattach active persisted runs after the replacement scene is reconciled. `destroy()` closes admission and attempts every editor/receiving cleanup even when a child fails.

`WorkspaceConversationProjection` owns streamed-content overrides, hydrated snapshot merging and bounded post-generation refresh. It retains content with a newer document version or a more complete document at the same version, while accepting incoming metadata. Active, mounted and canvas-referenced conversations survive partial hydration updates. Refresh ports receive the originating workspace and conversation identity; stale responses cannot replace a later refresh or publish into another scene. Clear the projection on scene replacement and destroy it with the view to release retry timers.

`WorkspaceCanvasMembership` under `/shared` runs attach/detach preparation inside the persistence controller's write lock. It assigns the next canvas revision, validates the Asset acknowledgment and adopts accepted state into the originating session. Preparation receives the latest session snapshot; view adapters must reject obsolete preparation before transport and must guard direct DOM updates after awaiting transport. Accepted transport results remain session-owned after the view leaves. The viewport-stash helpers use the product's versioned storage key and the engine's viewport comparison; storage access belongs to the supplied host.

`WorkspaceViewportPersistence` owns a view's viewport debounce, leading/trailing commits, unload stash and restoration. It acquires a session lease and registers its pending work with session flush/close. Its host supplies live canvas state, viewport restoration, timers and storage. `destroy()` submits pending viewport work and releases the view without cancelling accepted writes. Cancelled timer callbacks cannot submit later updates. Unload stashing includes explicit viewport writes awaiting acknowledgment, even when the leading write was already submitted.

`WorkspaceCanvasSessionHub` under `/shared` retains one session per workspace. Views acquire and release leases without closing that session. The session's `CanvasPersistenceController` serializes canvas saves and membership callbacks, coalesces pending snapshots and preserves explicit viewport intent. It keeps versions per workspace, bounds stale retries and refreshes authoritative topology through its fetch port. Store publications include workspace identity and origin; the application adapter must reject publications for another active workspace and must not mark authoritative state dirty.

`flush()` retries retained work and waits for it. `drain()` waits for accepted work and rejects if a failure remains unresolved. `close()` stops admission and drains; the hub waits for every session even when one fails. Release view leases during disposal, then explicitly drain and close the hub when its application owner shuts down. Accepted transport writes are not cancelled by view disposal. Canvas defaults, load normalization and local-versus-authoritative dirty-state patches are also exported under `/shared`.

`WorkspaceOutputDetails` composes editable Asset metadata, descriptor tags, registered Artifact info views, history projections and fallback progress. Supply Asset/editor ports and the installed Artifact definition; concrete Capability implementations stay in their modules. Media and branch history are supplied through typed mounts with an abort signal. The component owns returned views, releases partial mounts on failure and routes progress updates only to the selected output. Import `/styles/output-details-content` alongside the sidebar frame stylesheet. The history editor owns any progress view it publishes through `onProgress`; the details component owns its fallback timeline.

`/frontend/workspace` exports `WorkspaceRightPanel`, the Lixpi composition of UI-kit's SidePanel and SlidingSwitch. It switches between Capabilities, Artifacts, Media and AI Threads through a scoped content port. UI-kit owns resizing, slide motion and the switch's default flat appearance; the Lixpi wrapper does not override that appearance. The workspace owner retains the live mode switch during content replacement, cancels obsolete frames and guards close/open completions. Supply persisted state, behavior settings and a pane-local pan lock. Mounting the panel does not create an editor or import an application store. Import `/styles/right-panel` for its layout. Each canvas owns its own panel, controls and content lifetime.

`/frontend/composer` exports `createAiPromptComposer` and `WorkspacePromptComposer`. The former owns an editor shell, gradient and callbacks through a typed editor port. The workspace wrapper supplies the bottom-center layout and keeps the prompt draft under a workspace-specific storage key. Draft writes never enter canvas persistence or change the viewport. Appearance and editor infrastructure are explicit inputs; model-control factories remain in the application editor adapter.

`WorkspaceContextTrays` renders the supplied explicit context-node list beside the composer or in a conversation panel. It owns preview instances and remove listeners, releases disconnected trays and updates its content without remounting the editor. Import `/styles/workspace-composer` for the workspace layout and chip styles.

## Context previews

`/frontend/context` projects Asset and Capability metadata into preview tiles for canvas chips, prompt references and conversation history. UI-kit supplies the generic popover and artwork. The environment supplies document text, registered Artifact icons, initial rendition URLs, authorized rendition resolution and tooltip timing. Import `/styles/context-preview` for the Lixpi preview presentation.

Each tile owns separate trigger and popover media lifetimes. Opening refreshes metadata and replaces the previous popover content. Replacing or destroying content aborts its pending media requests and releases native video sources. The canvas portal resolver finds the owning pane and viewport scale; ordinary application previews retain UI-kit's placement behavior.

Media-reference labels prefer canonical Asset titles. Capability references load published description metadata on demand, show a retry after failures and share requests only through an explicitly supplied `CapabilityModulePromiseCache`. Clearing that cache prevents rejected requests from an earlier epoch from evicting replacement entries. Branch prompt renderers compose these previews with UI-kit artwork; editor atom navigation remains in the ProseMirror integration.

## Workspace libraries

`/frontend/library` exports the embedded Capability, Artifact and Media library panels. Import `/styles/library-panels` for their browse/inspector layout and shared row-action buttons. Primary Add, Accept and Use actions use `capability-library-row-action-primary`; secondary inspection and navigation actions use `capability-library-row-action`. UI-kit owns the surrounding SidePanel and generic controls.

The Capability panel receives an authorized catalog client and displays Tools and their public details. Internal Skills remain outside that list. The Artifact panel receives the installed shared/frontend registries and delegates schema validation, catalog metadata and view creation by Artifact type. Neither panel imports a concrete Capability module.

Artifact and Media libraries receive `WorkspaceLibraryPorts` for Asset reads, revisioned mutations, document snapshots and history mounting. Media also receives an authorized rendition URL resolver, the content editor port and identity/catalog-removal actions. Transport ports commit authoritative store updates even when the view has been disposed. The component owns editor/view disposal and ignores obsolete catalog, inspector and mutation responses. `unmount` releases resources but allows remounting; `destroy` is terminal.
